# dsh-boss-whale

把「每天刷 BOSS 直聘」做成一条**会自己按时干活**的鱼：到点开一个真浏览器，像人一样打开搜索页、慢慢往下滚、偶尔点开一个岗位看看，把看到的岗位记下来，去重排序后整理成日报投进 DSH 的专用会话。

改造自 [dsh-bili-whale](https://github.com/Alterssss/dsh-bili-whale)，保留了它的三层骨架（设置页 section / 生物钟 tick / 会话投递），把 B 站那套业务逻辑换成了求职检索。

## 它做什么

| 做 | 不做 |
|---|---|
| 开真浏览器，按人的节奏浏览职位列表 | ❌ 不投简历、不上传附件 |
| 去重（同一个岗位只播报一次） | ❌ 不群发：**每天最多 2 条招呼，服务端硬上限** |
| 按命中度排序，生成日报 + 招呼语草稿 | ❌ 不点「立即沟通」、不改你的账号状态 |
| 在设定窗口里每天跑 N 轮 | ❌ 不绕验证码：撞到验证就停手，等你来过 |
| （可选）每天最多跟 2 位 HR 打招呼 | ❌ 不替你谈薪资、约面试、给微信 |
| （可选）对方回话时按规则接一句，接满就交回你 | ❌ 不在被拒绝后继续纠缠 |

**关于自动打招呼的边界。** 批量群发是平台明令禁止的，代价是账号被限 —— 而这个插件本来就是为了找工作，把账号搞死等于自我否定。所以这里不是"开放了群发"，而是**把人本来会做的那一两下机械化，并且加上人的节制**：

- 每天 **0 / 1 / 2** 条，默认 **0**（只出草稿）；`2` 是代码里的硬上限，改配置文件也突破不了
- 同一个岗位（按内容指纹）**永远只打一次**，HR 重新发布换了 id 也不重打
- 只在设定时间窗口内发，凌晨不会突然冒出一句"您好"
- 额度按天记在账本里，DSH 重启不清零

## 虚拟人：为什么不用接口，也不开 headless

这是整个插件唯一"非它不可"的技术决定，值得单独说清。

BOSS 的职位接口不接受「浏览器里的 cookie 拿到 node 里回放」。实测（同一台机器、同一份刚扫码拿到的 fresh cookie）：

| 方式 | 结果 |
|---|---|
| node 直连，带一模一样的 cookie | `code 37 您的环境存在异常` |
| node 直连，换成浏览器真实 UA（Edg/150） | 还是 `code 37` |
| headless 浏览器，**页面内** fetch | 还是 `code 37`，而且 `navigator.webdriver=true`、UA 里带 `HeadlessChrome` |
| headless 再撞几次 | 升级成 `code 35 您的IP地址存在异常行为`（IP 级限流） |
| **有头浏览器 + 关掉 AutomationControlled** | 页面正常打开，能读到岗位 |

原因很直白：`__zp_stoken__` 是页面 JS 现算的，跟运行环境绑在一起；headless 等于举着手说"我是脚本"。所以：

- **永远不开 headless**（代码里没有任何 `--headless` 分支，这不是"默认值"，是硬约束）
- 不开 headless 的代价是窗口会真的弹出来。不想看见就把「窗口挪到屏幕外」打开 —— 仍然是"有头"，只是你看不到
- 读的是**渲染后的 DOM**，不是接口返回的 JSON。所以页面改版时它会说"没读到卡片"，而不是假装"今天没岗位"

### 节奏参数只允许调慢

| 参数 | 默认 | 说明 |
|---|---|---|
| 慢慢来 | 开 | 每一步停 1.5–4 秒 |
| 每屏滚动几段 | 5 | 2–12，滚动中间会随机停顿、偶尔往回滚一点 |
| 每屏停留 | 8 秒 | 读完再走 |
| 每轮点开几个岗位 | 1 | 随机挑一个点进去、滚两下、按"返回"回来 |
| 每轮看几屏 | 1 | 翻页是点「下一页」按钮，不是改 URL 参数 |

服务端对这些值都再 clamp 一次：`scrollSteps` 写 1000 会变成 12，`dwellSec` 写 0.1 会变成 1。**没有一个开关能让它变快** —— 想省时间应该减少轮数，而不是压缩每一步的停留。

### 撞到验证：把方向盘交回给人

它自己过不了人机验证（也不该去绕）。所以撞上时：

- **在终端里手动跑**（`daily --dry`、`browse`）→ 窗口留着，提示你在窗口里过验证，每 3 秒看一眼，最多等 3 分钟；过了就自动接着逛
- **调度器跑**（无人值守）→ 立刻停手，不干等，直接进冷却期

冷却期落盘在计划状态里，调度器、命令行、设置页看到的是同一个结论：

| 拦下来的原因 | 停多久 |
|---|---|
| `code 35` IP 异常 | 3 小时 |
| `code 37` 环境异常 | 1 小时 |
| 人机验证 | 2 小时 |

同一类问题在**冷却期没过时又去撞**会翻倍（封顶 4 倍）；老老实实等满再来，只按基准算 —— 认真等的人不该被越罚越久。冷却期间点「立即跑一轮」会被直接拒绝，连一个页面都不打开。

## 自动接话：什么会回，什么一定不回

打完招呼后，对方回话可以自动接一句。但**只有不需要做承诺的话**才自动回：

| 对方说的话 | 插件怎么做 |
|---|---|
| 一般性介绍、反问、"还在看机会吗" | 回一句，顺势问一个具体问题 |
| 要简历 / 作品集 | ⚠ 交回你本人（附件得你发） |
| 要微信 / 电话 / 邮箱 | ⚠ 交回你本人 |
| 约面试 / 什么时候方便 | ⚠ 交回你本人（时间得你定） |
| 谈薪资 / 期望 / 年包 | ⚠ 交回你本人（口径只能你说） |
| 已招满 / 不合适 / 谢谢关注 | ✓ 直接结束，不再回 |

每个会话最多自动接 `maxTurns` 句（默认 2），接满交回你；每天自动接话总预算默认 6 句。**说错了是替你丢 offer**，所以设计上宁可少说一句。

## 扫码登录：两条路线，按环境自动选

dsh-bili-whale 能在设置页里直接画出二维码，是因为 B 站有公开的扫码三件套（generate / poll / Set-Cookie）。**BOSS 没有** —— 它的登录页是 `zhipin-sign` 签名应用，二维码由前端画布渲染，生成接口名没有公开契约（试过十余个候选路径全 404）。就算猜对一个，后面还有配套的轮询接口和 stoken 交换要一一对上，猜错的表现是「二维码画出来了但永远不成功」，比没有入口更误导人。

所以这里统一的做法是：**打开官方登录页，你扫码，我从浏览器里读登录态**（含 HttpOnly，`document.cookie` 读不到的那些）。用哪个浏览器看环境：

| 路线 | 什么时候用 | 读 cookie |
|---|---|---|
| ① Electron 内嵌窗 | 宿主能拿到 `electron.BrowserWindow` | `session.cookies.get({ url })` |
| ② 本机 Edge / Chrome | 宿主拿不到 Electron（DSH 0.2.x 就是这样） | 独立 profile 起浏览器 + CDP `Storage.getCookies` |

两条都是"扫码 → 自动取登录态 → 自动关掉窗口"，区别只在窗口从哪来。DSH 0.2.x 里宿主插件跑在 Node 侧，`require('electron')` 拿到的是**可执行文件路径字符串**（不是模块），`BrowserWindow` 永远是 undefined —— 所以实际走的是 ②。设置页里那个「改用浏览器」按钮可以手动指定走 ②，方便排查。

路线 ② 的五个步骤（也是五个容易翻车的点）：

1. 用**独立 profile** 启动：`--remote-debugging-port=0 --user-data-dir=~/.boss-ai/browser-profile`；
2. 端口不猜，从 profile 目录的 `DevToolsActivePort` 里读（Chrome 自己写的）；
3. 等 page target 出现，连 CDP（自带极简 WebSocket，零依赖）；
4. `Storage.getCookies` → 只留 zhipin 域 → 三字段判断；
5. 验证 + 落盘，然后 `Browser.close`。

**为什么必须独立 profile**：复用你日常的 profile 时，浏览器已经在跑，新进程只会把 URL 转发给已有实例然后退出，调试端口根本不会打开。这是这类功能最常见的「在我这儿不生效」，而且现象是"点了没反应"，很难往这个方向想。代价是第一次要在这个新 profile 里扫一次码；之后它有持久化登录态，再点就是秒过。

**为什么成功就关浏览器**：调试端口只监听 127.0.0.1，但留着它等于给本机任何程序开了一个读你账号的后门。所以登录态一落盘就 `Browser.close`，连进程一起收掉。

判定登录成功用三个字段齐活：`__zp_stoken__` + `bst` + `wt2`。**不看 `__zp_stoken__` 一个就下结论** —— 它是反爬令牌，未登录时也会被下发，只看它一定会误判。

拿到 cookie 后还会用 `/wapi/zpuser/wap/getUserInfo.json` 验一次（未登录时它明确回 `code 7`）。这里有个刻意的三档结论：

| 接口返回 | 判定 | 为什么 |
|---|---|---|
| `code 0` | 成功，并带出账号名 | 确实登录了 |
| `code 7`（登录状态失效） | `unverified`，**但 cookie 照样存盘** | 明确没登录；存下去才有机会人工排查 |
| `code 37`（环境异常）/ 请求本身失败 | 仍算 `success`，只在提示里注明没验通 | node 直连没有 JS 环境，被风控拦下是常态。判成失败会让人**反复扫码而永远扫不过** |

两条路线共用同一份判定标准（`lib/login-common.js`）：各写一遍的话，迟早出现"窗口登录认、浏览器登录不认"这种诡异差异，而两边都是"看着成功了"的状态。

登录窗口用独立的 `persist:boss-whale-login` 分区：不污染 DSH 自己的 session，也让 BOSS 认得"同一台机器的同一个浏览器"，反复登录不至于次次触发风控。

## 接口路径：这里是"未验证"，不是"已验证"

BOSS 的内部接口路径没有公开文档，会变，不同灰度账号也可能不同。所以这一层是「候选 + 探测 + 可覆盖」，而不是写死一条然后祈祷：

1. 内置候选只是起点；
2. **只自动探测只读接口**（会话列表）。"探测打招呼接口"本身就是在给陌生人发消息，那不叫探测；
3. 探测成功一次就缓存到 `~/.boss-ai/endpoints.json`，不反复试错；
4. 都不通时报 `unknown-path`，并告诉你去 DevTools 里粘真实路径（设置页「接口路径（高级）」）。

所以第一次「真发一条」如果失败，大概率是路径问题 —— 报错会明确说是"路径不存在(404)"还是"被风控拦了"，因为这两件事的修法完全不同（改一个配置 vs 停一天别动）。

## 去重为什么用两个主键

`encryptJobId` 由 `jobId` + 每次下发的 `securityId` 派生，**不是岗位的稳定标识**：HR 重新发布、或令牌轮换，同一个岗位就会拿到一个新 id。只按 id 去重，日报里会反复出现同一条 —— 而且因为它"看起来是新 id"，你根本不会怀疑去重坏了。

所以 `seen.json` 里存两份索引：

| 键 | 内容 | 作用 |
|---|---|---|
| `ids` | `encryptJobId → 首次见到的时间` | 精确命中，同一个 id 不重复 |
| `fps` | `内容指纹 → 首次见到的时间` | 兜住"换了 id 的同一岗位" |

指纹 = `sha1(公司 | 职位 | 城市 | 薪资)`，先做归一（去空格、全角括号、标点、大小写）。

两个刻意的取舍：

- **薪资保留在指纹里**。HR 把 20-30K 调到 25-35K，那是值得再看一眼的变化，不该被折叠。
- **不做过度归一**（比如抹掉城市区县、忽略职位名差异）。宁可少折叠一条，也不要误吞一条真实岗位 —— 重复播报只是烦，漏掉一个机会是损失。

旧格式（只有 `ids`）会自动从 `jobs.jsonl` 回填指纹，不需要手工迁移；两份索引都按 90 天清理。

日报里"同一岗位换 id 重发"是**单独计数**并写出来的，不静默丢弃 —— 否则去重失效时你毫无察觉。

## 安装

```bash
# 1. 放到插件目录
cp -r dsh-boss-whale ~/.dsh/plugins/

# 2. 登记到 profile（bundles 才是挂载清单，只写 dependencies 不生效）
#    ~/.dsh/profiles/desktop/package.json
#      dsh.profile.bundles 追加 "dsh-boss-whale"
#      dependencies 追加 "dsh-boss-whale": "link:C:/Users/<你>/.dsh/plugins/dsh-boss-whale"

# 3. 让 pnpm 建链接
dsh plugin --profile desktop add "link:C:/Users/<你>/.dsh/plugins/dsh-boss-whale"

# 4. 重启 DSH
```

无第三方依赖，不需要 `npm install`。

## 用

**设置 → 求职**（左栏，在“通用”和“模型”之间）

1. **扫码登录**（推荐）：点「扫码登录」→ 打开 BOSS 官方登录页（DSH 窗口或本机 Edge/Chrome，看环境自动选）→ 手机 BOSS App 扫码 → 成功后自动取登录态并关掉窗口。
   如果那个浏览器 profile 里还留着上次的登录态，会直接复用，不用重扫（状态行会写"已接上"）。
2. 或者手动粘 cookie（兜底）：zhipin.com → F12 → **Network → 点任意一个 zhipin 请求 → Headers → Request Headers → `cookie` → 右键 Copy value**，然后点设置页的「从剪贴板填入」。
   这条路能把 HttpOnly 的 `__zp_stoken__` 一起带出来；Application → Cookies 里整行复制也可以。别用 `document.cookie` —— 它读不到 stoken。
3. 填关键词 / 城市 / 最低薪资 / 排除词。
4. **浏览方式**保持「虚拟人」（另一项「接口直连」只用于对照，正常别选）。
5. 设时间窗口（默认 09:30–11:00）、每日轮数（默认 2）、两轮最小间隔（默认 180 分钟）。
6. 点 **保存** → 点 **开窗过验证 / 登录**，把这个浏览器里可能存在的验证过一下（过完直接关窗）→ 想立刻看效果就点 **立即跑一轮**。
7. **试跑**：在「试跑」区填一个词再点「立即跑一轮」，只跑这一次 —— 不改配置、不记入去重。想对比两个关键词的输出就用它。

第一次点「立即跑一轮」时窗口会自己弹出来、自己滚动，别去动它。它可能中途停下并报「页面弹了人机验证」—— 那说明这个 IP 需要人工过一次，走第 6 步。

**会话**：工作区 → 未分组 → `boss-whale`。插件起来后约 8 秒自动创建（并打一句招呼说明自己是谁），
不用等第一轮跑完才有窗口。`digest.seedSession = false` 可以关掉这个行为（只报送、不占会话列表）。
新会话默认权限不是完全访问，想让她在里头自己跑命令，跟对待那个养鱼会话一样：打开它 → 权限 → 完全访问。

## 命令行

```bash
node tools/boss.mjs selftest          # 体检（设置页「体检」按钮调的就是它）
node tools/boss.mjs login --cookie "..."   # 也可以走命令行写登录态
node tools/boss.mjs browse            # 开窗停在搜索页，让你手动过验证/登录（不抓任何东西）
node tools/boss.mjs search            # 逛一轮，只打印，不落盘
node tools/boss.mjs daily --json      # 逛 + 去重 + 落盘 + 生成日报（调度器调它）
node tools/boss.mjs daily --dry       # 试跑：只看不记；在终端里跑会把窗口留给你过验证
node tools/boss.mjs daily --keyword=React --dry   # 临时换词试跑
node tools/boss.mjs daily --mode=api  # 对照用：走 node 直连（一定 code 37）
node tools/boss.mjs daily --force     # 忽略冷却期硬跑一次（想清楚了再用）
node tools/boss.mjs daily --greet     # 逛完顺带打一条招呼（受每天 2 条上限约束）
node tools/boss.mjs greet --dry       # 只挑人 + 写话，不发送（随便试）
node tools/boss.mjs greet --json      # 真发一条（一次只发一条，不做批量循环）
node tools/boss.mjs replies           # 看对方回了什么（只读：不落盘、不发送）
node tools/boss.mjs replies --auto    # 按规则自动接话 / 交回人工
node tools/boss.mjs probe             # 探测读接口路径（只读）
node tools/boss.mjs risk --clear      # 清掉风控冷却（招呼侧和抓取侧一起清）
node tools/boss.mjs plan              # 看下一轮什么时候跑（冷却中会直接说）
node tools/boss.mjs status            # 看配置 / 登录态 / 浏览方式 / 冷却 / 今日进度
```

```
tools/lib/plan.mjs  生物钟纯函数（窗口 / 轮数 / 间隔 / 概率跳过 / 冷却优先）
tools/lib/store.mjs 去重、打分、日报、招呼语模板
tools/lib/greet.mjs 打招呼/接话的**策略层**：额度账本、挑人、写话、handoff 规则（不碰网络）
tools/lib/chats.mjs 打招呼/接话的**传输层**：唯一有副作用的文件（候选路径 + 探测 + 可覆盖）
tools/lib/config.mjs 默认配置 + 城市编码表（宿主和命令行共用，避免两套配置）
```

策略层和传输层拆开的理由：能不能发、该不该发、发哪句都是确定性逻辑，可以离线测；真正发出去只有一个函数。混在一起时，"额度算错"和"接口 404"会报成同一个错误，而这两件事的修法完全不同。

## 取舍记录：几种看着对、实际会静默失灵的写法

改这个插件时最容易被"看起来更短"的写法带偏。下面这几条都是踩过的，记下来免得再走一遍：

| 被否掉的写法 | 为什么会坏 | 改成什么 |
|---|---|---|
| `execFile(process.execPath, [script])` | 在 Electron 里 `process.execPath` 是**应用自己**，不是 node。跑脚本会静默返回 0，你以为成功了，其实一个字都没执行 | `resolveNodeRuntime()`：真的找 node、真的跑一遍、真的检查产物 |
| `setInterval(60_000)` + `toTimeString().slice(0,5) === '09:30'` | 定时器的相位和整分钟不对齐。运气不好同一分钟触发两次，或者整分钟被跳过 —— 而且没法表达"今天已跑 2 轮，够了" | 60 秒 tick + `plan` 状态机（窗口 / 轮数 / 最小间隔 / 概率跳过） |
| `apply()` 里 `const cfg = readConfig()` 然后闭包持有 | 设置页改了配置不生效，必须重启 DSH。而人不会想到要重启，只会觉得"保存了没用" | 每次 tick 重读配置 |
| 白名单手抄一份 `['search','fetch',...]` | 和 `DEFAULTS` 迟早走散。漏一个键的症状是"保存成功，重启后值又变回去"，全程不报错 | `new Set(Object.keys(DEFAULTS))` |
| 未知键直接丢掉 | 键名拼错时用户只看到"点了没反应" | 回 `ignored: [...]`，界面直接显示"这些键不认" |
| 只查顶层未知键 | `greet.maxPerDay` 拼成 `maxPerDayy` 能存进去、不报错、也不生效 —— 比顶层拼错更隐蔽 | 嵌套层一起查，回报 `greet.maxPerDayy` |
| 「每天上限」只在前端限制 | 配置是磁盘上的 JSON，手改成 50 就绕过了一道产品约束 | 服务端再 clamp 一次（`HARD_MAX_PER_DAY = 2`） |
| 「看回复」和「自动接话」共用一次落盘 | 你点一次「看回复」，账本就把那条消息标成处理过，自动接话永远接不上它 —— 看一眼把功能看坏了 | 只读走 `structuredClone` 副本，`--auto` 才 `saveLedger` |
| 自动发送失败后每 5 分钟重试 | 对同一个 HR 反复敲门，比不回更糟 | 失败即 `handoff`，只播报一次 |
| 用 `encryptBossId` 顶 `jobId` 去打招呼 | 那是**老板**的 id，不是岗位 id；要么接口报错，要么打错对象 | `normalize()` 单独留出 `encryptJobId`，缺了就不发 |
| 猜 BOSS 的二维码接口，自己在设置页画码 | 登录页是签名应用，接口名没有公开契约（实测十余个候选全 404）。猜错的症状是"码画出来了但永远不成功"，比没有入口更误导 | 开官方登录页，从 cookie store 里取（`lib/qr-login.js`） |
| 用 `document.cookie` 取登录态 | `__zp_stoken__` 等关键字段是 HttpOnly，脚本里读不到 —— 拿到的是个看起来像 cookie、但抓取必回 `code 37` 的半截字符串 | Chromium cookie store（`session.cookies.get`），HttpOnly 也能读 |
| `const el = require('electron')` 然后直接用 `el.BrowserWindow` | 纯 node 下 `require('electron')` **不报错**，返回的是一个可执行文件路径**字符串**。报错会变成 "Cannot read properties of string"，和真正的原因（不在 Electron 里）毫无关系 | 显式检查 `typeof el.BrowserWindow === 'function'`，失败给一句人话 |
| 登录成功标志 = 出现 `__zp_stoken__` | 它是反爬令牌，**未登录也会下发**。只看它会在没登录时就报"已登录"，然后抓取全崩 | 三字段齐活（`__zp_stoken__` + `bst` + `wt2`），再用 getUserInfo 验一次 |
| 验证失败就判登录失败 | node 直连没有 JS 环境，`code 37` / 断网都是常态。判失败会让人反复扫码、永远扫不过 | 三档：`code 0` 成功；`code 7` 才算没登录；`37`/网络错误算"已保存但没验通" |
| 关窗事件里无条件 `status = 'cancelled'` | 登录成功会自己关窗，于是刚写完 `success` 就被改回 `cancelled` —— 最典型的"明明登录了却显示失败" | 先置 `settled` 再 `close()`，`closed` 里看到 `settled` 就不翻案 |
| 扫码成功时调 `load()` 刷新界面 | `load()` 会重置 draft，用户正在改的配置被无声抹掉 | 只刷 `credentials` 徽章（`refreshCred`），不碰 draft |
| 用 `globalThis.WebSocket` 连 CDP | 它只在 Node 22 才稳定存在，而宿主 Node 版本随 Electron 走 → "我这儿能跑、别人那儿 undefined"，最难查的一类问题 | 自己实现 RFC6455 的握手和帧（`lib/cdp.mjs`），跟运行时版本无关 |
| 复用你日常的浏览器 profile 去开调试端口 | 浏览器已在跑时，新进程只把 URL 转发给已有实例然后退出，`--remote-debugging-port` 根本不生效。现象是"点了没反应" | 独立 profile（`~/.boss-ai/browser-profile`），端口从 `DevToolsActivePort` 读 |
| 猜一个固定调试端口（9222 之类） | 端口被占就整条链路失败，而且报错是"连不上" —— 无法区分"没起来"和"被占了" | `--remote-debugging-port=0` 让 Chrome 自己选，再从 profile 里读回来 |
| 只调 `Network.getAllCookies` | 它被标了 deprecated，不同 Chromium 版本/策略下可用性不一样，症状是"连上了但永远读不到 cookie" | 先 `Storage.getCookies`，失败再退到 `Network.getAllCookies` |
| 走 WS 时带上 `Origin` 头 | Chrome 111+ 起 DevTools 端点会拒绝带 Origin 的连接（除非启动加 `--remote-allow-origins`），报错是握手 403 | **故意不发 Origin**（本地进程直连是放行的） |
| 所有登录失败都自动降级 | 起浏览器失败 / 调试端口被安全软件拦是真故障，吞掉再降级只会剩一句含糊的"登录失败"，完全没法排查 | 只有 `no-electron` / `no-browser`（环境缺件）才降级，真故障原样抛出 |
| 登录成功后不关浏览器 | 调试端口留着 = 给本机任何程序开了个读账号的后门 | 落盘后立刻 `Browser.close`，连进程一起收 |
| 只读 zhipin 之外的 cookie 也一起存 | 浏览器里有别的站的登录态，一起写进 `credentials.json` 等于扩大了泄露面 | 按 domain 过滤（`isZhipinCookie`），只留 `*.zhipin.com` |
| 抓取走 node 直连接口 | 浏览器里刚生成的 cookie 拿到 node 回放，必然 `code 37`；换 UA 也没用。而且这条路"看起来很快"，会诱导你把轮数调高，最后把 IP 撞进 `code 35` | 虚拟人：有头浏览器读 DOM，慢，但这就是"人类流量"本来的样子 |
| 用 `--headless` 提速 | `navigator.webdriver=true` + UA 带 `HeadlessChrome`，等于自带"我是脚本"标签，一进去就是 37 | 硬性不开 headless；嫌窗口碍事就用"窗口挪到屏幕外"（仍有头） |
| 撞到验证就重试 | 60 秒后再撞一次，三次之后 IP 就从"环境异常"升级成"IP 异常"，连你正常用浏览器都会被要求验证 | 落盘冷却期（35 → 3h / 37 → 1h / 验证 → 2h），调度器看到就彻底不动 |
| 冷却期内再撞也按同一档算 | 认真等满的人一次不落，撞一次就翻倍，越守规矩越久用不了 | 只有"冷却没过又去撞"才翻倍；等满再来按基准算 |
| 看到"验证"关键词就停工 | 广告位 / 页脚偶尔也出现这类词，会变成"抓到 20 条却报风控"的假警报 | 已经有卡片就判正常；只有 0 条时才认这些词 |
| 报错文案统一说"重新登录试试" | `code 35` 跟 cookie 无关，重新登录一百次也没用，还会把 IP 撞得更狠 | 35 / 37 / 验证 / 掉登录四种情况各说各的动作 |

反过来，有几条是从另一版实现里**留下**的：白名单从默认值推导、"试跑某个关键词"这个入口。后者有个细节必须成对：试跑要 `--dry`（只看不记），否则你随手试一个词，那批岗位就被标成"看过"，定时日报再也刷不出来。

## 环境变量（都不设也能用）

| 变量 | 作用 |
|---|---|
| `BOSS_WHALE_BROWSER` | 指定浏览器可执行文件（装在非常规路径时） |
| `BOSS_WHALE_BROWSER_ARGS` | 追加启动参数，如 `--proxy-server="http://127.0.0.1:7890"`（支持引号） |
| `BOSS_WHALE_NO_BROWSER=1` | 禁用路线②，只用 Electron 窗口 / 手动粘贴 |

## 已知限制

- **薪资数字读不到**。BOSS 把薪资里的数字编成自定义字体的私用区字符，DOM 里读出来是乱码
  （页面看着正常）。目前的处理是「读不到就不念」，宁可少一句也不把乱码发出去。
- **岗位卡片上的标签是混的**：`.tag-list` 里既有任职要求（经验不限、学历不限、五险一金）
  也有技术标签（Vue、React）。`human.mjs` 的 `isTechLabel()` 负责筛，规则是黑名单式的，
  出现新的要求类文案会漏进去 —— 看到招呼语里冒出奇怪的字，去补那条正则。
- **虚拟人要开窗口**。默认真的有头、真的弹出来，会打断你看别的窗口。工作时可以勾「窗口挪到屏幕外」（仍然是有头浏览器，只是看不见）。
- **IP 级别的限流只能等**。`code 35` 不是 cookie 问题，也不是代码问题 —— 停手就行。冷却期写进计划状态，DSH 重启也不清。
- **它会撞到人机验证**，而且过不去。这是设计：过验证是人的动作。撞上时终端里会等你，设置页有「开窗过验证 / 登录」按钮专门给它用。
- **页面改版会让它读不到卡片**。DOM 提取器先用结构化 class，再退到"链接里带 `/job_detail/` 的都算卡片"。两级都失效时会明确报 `empty`，而不是假装"今天没岗位"。
- **`__zp_stoken__` 仍会过期**（几小时到一天）。失效时表现是掉登录（跳登录页），不是 37 —— 重新扫码一次即可。
- **路线② 会在 `~/.boss-ai/browser-profile` 留一个 Chromium profile**（几十 MB）。删掉它等于清空那边的登录态，下次要重新扫码；想省空间就删，不影响已保存的 cookie。
- **虚拟人也复用了这个 profile**（同一台机器上一次登录，两处都用），所以里面可能有你手动浏览过的痕迹 —— 这是"像人"的一部分，别介意。
- **路线② 需要本机有 Edge / Chrome / Chromium**。都没有时按钮会明确报"没找到可用的浏览器"，此时退回手动粘贴。装在非常规路径时用 `BOSS_WHALE_BROWSER=D:\...\chrome.exe` 指定。
- **起浏览器时调试端口在本机是开着的**（只在浏览/登录进行中，结束后立刻 `Browser.close`）。安全要求极高的环境可以设 `BOSS_WHALE_NO_BROWSER=1` 禁掉浏览器两条路线，只用粘贴 + 接口直连。
- **接口字段随时可能改版**。`api.mjs` 里结构解析失败时会给明确的 `parse` 错误，而不是静默返回空列表。
- **打招呼 / 发消息的接口路径未经验证**（会话列表接口会自动探测，但会发消息的那两个不探测）。首次「真发一条」失败是正常结果，报 `unknown-path` 时按提示粘真实路径即可。
- **消息方向靠猜**。会话列表接口不保证告诉你"最后一句是谁说的"，所以用「文本是否等于我发过的最后一句」+「文本与时间是否都没变」来判断。拿不准时动作是**等**，不是回。
- 自动接话是**模板 + 分类器**，不是大模型。它不会读懂上下文，也因此不会说出很漂亮的话 —— 但也不会替你乱承诺。想聊得更有内容，把 `maxTurns` 设成 0，全部交回自己。
